# Smart-Apartment-Vistor-Entry-Complaint-Management-System
Smart Apartment Vistor Entry &amp; Complaint Management System [6th Sem Project]

## Run frontend and backend

The frontend is served on port 3000 and proxies `/api/*` requests to the
backend at `http://localhost:8080` by default. Start the backend with a valid
database password configured locally, then start the frontend from `frontend`.

The backend has the Aiven MySQL URL configured as a default. Set the database
password in the backend terminal before starting it; override `DB_URL` or
`DB_USERNAME` there if needed:

```powershell
# Set the rotated Aiven password locally; do not commit it to source control.
$env:DB_PASSWORD = "<your Aiven MySQL password>"
cd F:\Project-6sem\Smart-Apartment-Vistor-Entry-Complaint-Management-System-main\backend
.\mvnw.cmd spring-boot:run
```

In another terminal, start the frontend:

```powershell
cd F:\Project-6sem\Smart-Apartment-Vistor-Entry-Complaint-Management-System-main\frontend
bun run dev -- --port 3000
```

Set `BACKEND_URL` if the backend is listening at a different address. The
browser uses the frontend's port 3000 for both pages and API requests.

## EP-02: Flat and resident management

- Administrators manage flats and their assigned residents at `/admin/flats`.
- Administrators can generate a persistent QR identifier for each flat; the UI
  renders it locally as a QR code.
- Authenticated security guards and administrators can scan a flat QR with a
  camera or enter its identifier at `/security/flat-qr`. The backend validates
  the identifier against registered flats.

## EP-03: Visitor entry and exit management

- Guards record visitor entry at `/security/visitors` after scanning or entering
  a valid registered flat QR. Entry time is generated by the backend.
- Guards can record exit for an active visit. The backend sets the exit time,
  changes the status, and rejects duplicate exits.
- Authenticated administrators and guards can view visit history, newest first.
  Entry and exit actions are restricted to security guards.

## Initial administrator setup

The public registration endpoint does not create administrator accounts. To
bootstrap the first admin, configure these environment variables for the
backend before starting it:

- `ADMIN_BOOTSTRAP_FULL_NAME`
- `ADMIN_BOOTSTRAP_EMAIL`
- `ADMIN_BOOTSTRAP_PHONE`
- `ADMIN_BOOTSTRAP_PASSWORD` (at least 12 characters)

The backend creates the account as active only if no admin account exists.
The password is stored as a BCrypt hash. If bootstrap variables are omitted,
startup does not create an account; partial or invalid configuration fails
startup with an error. Configure the database connection in
`backend/src/main/resources/application.properties` as well. Once the first
admin exists, remove the bootstrap variables.
